# WhaleCore 内容与 GEO 系统 · 交互说明（审查稿）

> **用途**：给协作者 / 审查人看的**整套系统交互说明**，不是官网挂载文案。  
> **配套短文**：[`content/changelog/README.md`](../content/changelog/README.md)（产品进化目录与同步开关）。  
> **运维细则**：[`docs/WORKSPACE.md`](WORKSPACE.md)。  
> **对外产品事实（公开仓）**：根目录 [`README.md`](../README.md) / [`README.en.md`](../README.en.md)。

请审查时聚焦：**信息流是否闭环、真源是否唯一、公开面是否利于 GEO 且不踩合规、运维是否可预期。**

## 0. 一句话

我们把「卖给站长的 AI 量化托管源码」拆成三套仓库：

1. **产品**能跑；  
2. **营销站**能询价、能被搜索/被 AI 引用；  
3. **内容工厂**能日更渠道 + 产出官网「产品进化」干净稿。  

进化稿经服务器同步进营销站上线，并**回推进公开的营销站 GitHub**，形成官网 + GitHub 双引用面。

## 2. 系统交互总览

```text
                    ┌─────────────────┐
                    │   WhaleCore     │
                    │ 产品源码/文档    │
                    │（能力真源·私有）  │
                    └────────┬────────┘
                             │ 卖点/能力可参考
                             │ 合规不以此仓为准
                             ▼
┌──────────────┐      ┌─────────────────┐      ┌──────────────────┐
│   Whapub     │      │     Whaint      │      │  公开引用面       │
│ 内容工厂     │      │ 营销站 + GEO    │      │                  │
│              │      │                 │      │ · 线上站         │
│ marketing/   │─────►│ content/        │─────►│   /changelog     │
│  changelog/  │ sync │  changelog/     │ build│   /llms.txt      │
│  (真源写稿)  │      │  (镜像·进 Git)  │      │   /product …     │
│              │      │                 │ push │ · GitHub 公开仓  │
│ marketing/   │      │ README 中英     │─────►│   README + md    │
│  channels/   │      │ compliance/     │      │                  │
│  (渠道草稿)  │      └────────┬────────┘      └──────────────────┘
└──────────────┘               │
                               │ Docker ./start.sh
                               ▼
                        访客 / 爬虫 / LLM
```

要点：

- **写稿真源**在 Whapub 的 `marketing/changelog/`（官方发布）。  
- **渠道草稿**在 Whapub `marketing/channels/`，**不自动上官网**。  
- Whaint 只消费「干净官方稿」；构建时 sparse 拉取后写入 `content/changelog/`。  
- 有变更则 **commit + push 回 Whaint**，公开 GitHub 上也有同一批 md（GEO 次级面）。  
- **营销合规真源**在 Whaint 根目录 `compliance/`（不是产品仓、不是 Whapub）。

## 3. 人怎么用（日常交互）

### 3.1 写「官方产品进化」（上官网 + GitHub）

1. 在 **WhalePub** 工作区按规则写 `marketing/changelog/{decision|weekly|note}/YYYY-MM-DD-{中文标题}.md`  
2. `git push` 到 Whapub  
3. 在 **Whaint 服务器**：`git pull` → `./start.sh start --build`  
4. 自动：同步 →（有变更）提交并推送 `content/changelog/` → 构建静态站  

结果：

- 线上 `/changelog` 可见  
- `/llms.txt` 带各篇中英摘要  
- GitHub 路径如 `content/changelog/decision/….md` 公开可读  

### 3.2 写渠道内容（小红书等）

- 只进 Whapub `marketing/channels/`  
- **不会**被 sync 进 Whaint  
- 人工发布到各平台；与官网 GEO 解耦  

### 3.3 改产品能力 / 部署

- 只动 **WhaleCore**  
- 营销站文案与合规仍走 Whaint；重大定位变化需同步公开 README 与合规目录  

### 3.4 改对外口径（合规 / 询价话术）

- 只改 Whaint `compliance/`，再同步营销站 `/compliance` 页  
- 禁止收益承诺；本站**询价制**，公开 README **不写死标价**

## 4. 产品进化条目约定（给审查）

目录（Whaint 镜像 = Whapub 官方区结构）：

```text
content/changelog/
  decision/   # 决策日志
  weekly/     # 周报精选
  note/       # 其它
```

Frontmatter 常用字段：`date` · `kind` · `title` · `titleEn` · `summary` · `summaryEn` · `source`（如 ADR-xxxx）。  
正文：中文在前，`<!--en-->` 后为英文。  
性质：**工程 / 产品决策笔记**，不是业绩报告，不作收益承诺。

短说明见：[`content/changelog/README.md`](../content/changelog/README.md)。

## 5. GEO 分层（为什么要回推 GitHub）

| 优先级 | 表面 | 内容 | 作用 |
|--------|------|------|------|
| **主** | 已部署营销站 | `/llms.txt`、`/llms-full.txt`、`/changelog`、产品/合规页 | AI/爬虫首选权威 URL |
| **次** | 公开 Whaint GitHub | 中英 README（含 30 秒摘要 / 原则 / AI FAQ）、`content/changelog/**/*.md` | 可核对原文、GitHub 高爬取权重 |
| **辅** | 私有 Whapub | 写稿真源 + 渠道草稿 | 不指望被公开引擎索引 |

### 知识引用优先级（与公开 README 一致）

冲突时：`compliance/` → 线上站 → 公开 README → `content/changelog/` → 渠道/互站素材（不得覆盖前几项）。

若只服务器同步、**不** commit 进公开仓：官网仍有文，但 GitHub 缺进化稿 → 次级 GEO 面断裂。  
因此构建默认：`SYNC_CHANGELOG_COMMIT=1` + `SYNC_CHANGELOG_PUSH=1`。

公开仓产品介绍（中/英）带界面示意截图与能力详解，面向「站长买源码」受众，不是 C 端炒币获客话术。  
**未采纳（有意不做）**：金融化品牌升级、官网首页架构墙、把第三方数据源画成鲸系产品、竞品对比表、另建 Timeline（已有 changelog）。

## 6. 服务器与凭证（交互契约）

典型命令：

```bash
cd Whaint
git pull
./start.sh start --build
```

构建前顺序：

1. `scripts/sync-changelog.sh` — 从 Whapub 拉官方 changelog  
2. `scripts/commit-changelog.sh` — 仅暂存 `content/changelog/`，有变更则 commit；再 push  
3. Docker 构建静态站并启动（默认端口 3080）  

**一把 PAT 共用（推荐）**：细粒度 Token 勾选仓库 **Whapub + Whaint**，「内容」读写；写入服务器 `.env` 的 `WHAPUB_TOKEN=`。  
脚本推 Whaint 时：`WHAINT_TOKEN` → `GITHUB_TOKEN` → `WHAPUB_TOKEN`。  

| 变量 | 含义 |
|------|------|
| `SYNC_CHANGELOG` | `0` 关闭拉取 |
| `SYNC_CHANGELOG_PUSH` | `0` 只上线不同步到 GitHub |
| `WHAPUB_TOKEN` | 读 Whapub；兼写 Whaint 时可复用 |

推送失败：**只警告，不挡网站上线**（官网仍有最新文；GitHub 可能暂时落后）。

## 8. 边界与风险（审查清单）

请重点确认：

1. **真源唯一**  
   - 官方进化稿：Whapub `marketing/changelog/`  
   - 合规：Whaint `compliance/`  
   - 渠道草稿不得冒充官网正文自动上线  

2. **公开仓安全**  
   - Whaint 公开后：无 `.env`、无 Token、无交易所/模型密钥  
   - 进化稿不含未公开 Prompt / 客户隐私  

3. **合规话术**  
   - 禁止稳赚/保本/资金盘配套  
   - 「托管」= 策略/运营模式，≠ 代持资金  
   - 样板收益 / 截图数据 ≠ 收益承诺  
   - 对外售价询价制，勿把渠道标价写进公开 README  

4. **GEO 预期**  
   - 主战场是线上站，GitHub 是增强  
   - 回推失败时官网仍可用，但公开仓会短暂不一致  

5. **运维预期**  
   - 必须 `--build`（或等价重建）才会同步+回推  
   - 仅 `./start.sh start` 不重建则不会拉新文
